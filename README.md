# AoS Security v3.4.3 — Anti-Spam 5/5/30 и бан ботов

Discord security bot prepared for Render.

## Обновление 3.3.1

В версии 3.3.0 ошибка отправки показывала только код `50035` (Invalid Form Body)
и скрывала поле, отклонённое Discord. Такой код сам по себе не устанавливает
точную причину отказа. Версия 3.3.1 нормализует запрос и улучшает диагностику:

- Опрос отправляется отдельно от фотографий, без дополнительного текста,
  вложений и embeds в запросе создания самого опроса.
- Явно передаётся `layout_type: 1`, отсутствующие эмодзи не уходят как `null`.
- В `/poll-photo` бот сначала публикует фотографии с подписями, затем опрос.
  В сообщении с фотографиями появляется ссылка на голосование.
- Если Discord однозначно отклонил опрос, бот удаляет свою только что созданную
  галерею. При сетевой неопределённости фотографии сохраняются, повторной отправки
  опроса нет — сначала нужно проверить канал.
- В личном ответе и Render Logs выводятся код, путь поля и код его валидации.
  Лог также указывает команду и этап `photos`/`poll`. Токены, тела запросов и
  исходные ссылки вложений в диагностический лог не попадают.

Для обновления с 3.3.0 нужны `src/polls.js`, `package.json`, `test/polls.test.js`
и этот README. `/security-status` и `/health` после запуска покажут `3.3.1`.
Код ошибки: [Discord JSON Error Codes](https://docs.discord.com/developers/topics/opcodes-and-status-codes).

## Голосования

Две новые команды публикуют встроенный опрос Discord в текущем канале:

| Команда | Что заполнить |
| --- | --- |
| `/poll` | `вопрос` и `варианты`, разделённые символом `\|`: `Да \| Нет \| Воздержусь` |
| `/poll-photo` | `вопрос`, `фото1`, `фото2`; при необходимости `фото3`–`фото5` и `подпись1`–`подпись5` |

Пример: `/poll вопрос:Когда играем? варианты:Сегодня \| Завтра \| В выходные часы:24`.
В `/poll-photo` фотографии загружаются прямо в поля команды, подписи необязательны.
Фотографии и опрос публикуются двумя сообщениями. Номер на фотографии совпадает
с вариантом в опросе. Выберите ответ в опросе Discord
и нажмите кнопку голосования. По умолчанию можно выбрать один ответ;
`мультивыбор:True` разрешает несколько. Голосование открытое: участники могут
просматривать, кто за какой вариант проголосовал.

- Обычный опрос: 2–10 разных вариантов, до 55 символов каждый; вопрос — до 300.
- Фото: 2–5 файлов PNG/JPG/GIF/WebP, до 8 МиБ каждый и до 20 МиБ суммарно.
  Заполняйте фото по порядку, без пропусков; подпись — до 52 символов.
- `часы`: целое число 1–768, по умолчанию 24. После срока Discord завершает опрос
  и подводит итоги. Голоса сохраняются при перезапуске или отключении AoS/Render.
- Фотографии повторно прикрепляются к сообщению, чтобы не зависеть от срока
  действия исходных ссылок из команды.
- Запуск — раз в 60 секунд на участника и раз в 10 секунд на канал для обеих
  команд вместе. Эти короткие ограничения сбрасываются при перезапуске бота.
- Поддерживаются обычные текстовые каналы и открытые ветки, включая посты форума.
  В каналах объявлений и личных сообщениях команды не создают опрос.

Создателю нужны права «Просматривать канал», «Отправлять сообщения»
(в ветке — «Отправлять сообщения в ветках») и «Создавать опросы».
Для фото также нужно «Прикреплять файлы». AoS Security нужны те же права,
а для фото дополнительно «Встраивать ссылки». Права проверяются в текущем канале.
Уровни OWNER/SECURITY ADMIN/MODERATOR относятся к защитным командам:
для голосований используются обычные права Discord.
Если создавать опросы должна только администрация, ограничьте эти команды
в настройках сервера → Интеграции → AoS Security.

Опрос нельзя изменить после отправки. При ошибке удалите сообщение и создайте
новое. Досрочное завершение отдельной командой в этой версии не добавлено.
Формат и сроки: [документация Discord Poll](https://docs.discord.com/developers/resources/poll).

## Anti-Spam v3.4.3

- От 5 сообщений за 5 секунд на одном сервере:
  обычным участникам даётся таймаут на 30 минут; ботам — бан.
- При отсутствии возможности забанить бот пробует исключить его с сервера.
  Если обе санкции недоступны, спам удаляется и ошибка фиксируется в логах.
- Боты с Administrator также проверяются. Люди-администраторы,
  владелец и ID из WHITELIST_USER_IDS сохраняют исключение.
- Защита от массовых упоминаний и вебхуков остаётся включённой.

## Обновление Render

1. Развернуть текущую ветку main.
2. Проверить SPAM_MESSAGE_LIMIT=5, SPAM_WINDOW_SECONDS=5,
   SPAM_TIMEOUT_MINUTES=30 в Environment, если они заданы.
3. Дать AoS права «Банить участников», «Модерировать участников»,
   «Управлять сообщениями», при необходимости «Выгонять участников».
   Роль AoS должна быть выше ролей ботов, которых нужно банить.
4. Проверить настройки через /security-status.

## Пороги и проверка

По умолчанию: 5 сообщений за 5 секунд, либо 6 разных пользователей/ролей,
упомянутых в одном сообщении, либо 2 сообщения с фактическим пингом
`@everyone`/`@here` в пределах окна. После срабатывания новые сообщения этого
отправителя также очищаются в течение минимум 30 секунд; при продолжающейся
активности этот период продлевается.

- `SPAM_MESSAGE_LIMIT`: целое число 2–100, по умолчанию 5.
- `SPAM_WINDOW_SECONDS`: целое число 1–300, по умолчанию 5.
- `SPAM_TIMEOUT_MINUTES`: целое число 1–40320, по умолчанию 30.

Если доверенный сервисный бот должен превышать эти лимиты, его конкретный ID
можно добавить в `WHITELIST_USER_IDS`. Такой ID полностью исключается из проверки;
роль Administrator для бота такого исключения не даёт.

Локальные тесты: `node --test` или `npm test` из корня проекта. Они проверяют
обычного бота, бота-администратора, несколько каналов, людей, вебхуки,
отсутствие прав, ошибки API, одновременные события и очистку очереди.
Тесты подменяют Discord API и не подключаются к живому серверу.
Тесты голосований также проверяют сериализацию через discord.js, права в канале,
ограничение повторных команд, загрузку фотографий, ошибки отправки и регистрацию
новых команд. Для них сначала выполните `npm install`, затем `npm test`.

## Access Control

AoS Security v3 поддерживает 4 уровня:

- `OWNER` — полный доступ.
- `SECURITY ADMIN` — управление защитой.
- `MODERATOR` — только просмотр статуса.
- `MEMBER` — только обычное использование и верификация.

Переменные Render:

```text
OWNER_USER_ID=ID_главы

SECURITY_ADMIN_ROLE_IDS=ID_роли1,ID_роли2

MODERATOR_ROLE_IDS=ID_роли1,ID_роли2
```

Права команд:

```text
/security-status
MODERATOR+

/verification-setup
SECURITY ADMIN+

/lockdown
SECURITY ADMIN+

/panic
SECURITY ADMIN+
```

Владелец Discord-сервера автоматически получает `OWNER`.
