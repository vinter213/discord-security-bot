# AoS Security v3.3 — голосования и Anti-Spam

Discord security bot prepared for Render.

## Голосования

Две новые команды публикуют встроенный опрос Discord в текущем канале:

| Команда | Что заполнить |
| --- | --- |
| `/poll` | `вопрос` и `варианты`, разделённые символом `\|`: `Да \| Нет \| Воздержусь` |
| `/poll-photo` | `вопрос`, `фото1`, `фото2`; при необходимости `фото3`–`фото5` и `подпись1`–`подпись5` |

Пример: `/poll вопрос:Когда играем? варианты:Сегодня \| Завтра \| В выходные часы:24`.
В `/poll-photo` фотографии загружаются прямо в поля команды, подписи необязательны.
Номер на фотографии совпадает с вариантом в опросе. Выберите ответ в опросе Discord
и нажмите кнопку голосования. По умолчанию можно выбрать один ответ;
`мультивыбор:True` разрешает несколько. Голосование открытое: участники могут
просматривать, кто за какой вариант проголосовал.

- Обычный опрос: 2–10 разных вариантов, до 55 символов каждый; вопрос — до 300.
- Фото: 2–5 файлов PNG/JPG/GIF/WebP, до 8 МиБ каждый и до 20 МиБ суммарно.
  Заполняйте фото по порядку, без пропусков; подпись — до 52 символов.
- `часы`: целое число 1–768, по умолчанию 24. После срока Discord завершает опрос
  и подводит итоги. Голоса сохраняются при перезапуске или отключении AoS/Render.
- Фотографии повторно прикрепляются к сообщению, чтобы не зависеть от срока
  действия исходных ссылок из команды.
- Запуск — раз в 60 секунд на участника и раз в 10 секунд на канал для обеих
  команд вместе. Эти короткие ограничения сбрасываются при перезапуске бота.
- Поддерживаются обычные текстовые каналы и открытые ветки, включая посты форума.
  В каналах объявлений и личных сообщениях команды не создают опрос.

Создателю нужны права «Просматривать канал», «Отправлять сообщения»
(в ветке — «Отправлять сообщения в ветках») и «Создавать опросы».
Для фото также нужно «Прикреплять файлы». AoS Security нужны те же права,
а для фото дополнительно «Встраивать ссылки». Права проверяются в текущем канале.
Уровни OWNER/SECURITY ADMIN/MODERATOR относятся к защитным командам:
для голосований используются обычные права Discord.
Если создавать опросы должна только администрация, ограничьте эти команды
в настройках сервера → Интеграции → AoS Security.

Опрос нельзя изменить после отправки. При ошибке удалите сообщение и создайте
новое. Досрочное завершение отдельной командой в этой версии не добавлено.
Формат и сроки: [документация Discord Poll](https://docs.discord.com/developers/resources/poll).

## Исправления Anti-Spam из v3.2

Обновление подготовлено на основе сохранённого архива `AoS-Security-v3.1-Roles.zip`.
В его обработчике Anti-Spam проверка `message.author.bot` пропускала все сообщения
ботов. Отдельная проверка Administrator также давала бы ботам иммунитет.
Лог сообщал об успешном таймауте даже при отсутствии прав или ошибке Discord.

Теперь:

- Чужие боты, в том числе с Administrator, проходят проверку Anti-Spam.
- При срабатывании бот получает бан. Если бан недоступен, но разрешено исключение,
  AoS пытается исключить его без бана. При неудаче лог явно сообщает об этом.
- Обычные участники получают прежний таймаут. Владелец сервера, люди с Administrator
  и ID из `WHITELIST_USER_IDS` сохраняют исключение из Anti-Spam.
- Сам AoS исключён из проверок: его сообщения и защитные баны не запускают
  собственные Anti-Spam/Anti-Nuke.
- Счётчик общий для отправителя во всех доступных AoS каналах сервера.
- Удаляется наблюдавшаяся серия сообщений, включая сообщения, пришедшие во время
  запроса к Discord. Старую историю до обнаруженной серии бот не чистит.
- Входящие вебхуки проверяются отдельно и удаляются при спаме. Для вебхуков
  приложений/подписок автоматическое отключение не реализовано: сообщения
  очищаются, а необходимость ручного отключения попадает в лог.
- Одновременные события не создают параллельные баны одного отправителя.
  Неудачные санкции при продолжающемся спаме повторяются не чаще раза в 30 секунд
  (либо раз в окно Anti-Spam, если оно больше).
- Очередь очистки ограничена 100 сообщениями на отправителя; переполнение
  отражается в логе. Ошибки прав и запросов больше не выдаются за успех.
- `/security-status` и `/health` показывают версию `3.3.0`; статус также показывает
  право на бан и права очистки/управления вебхуками в текущем канале.

## Как обновить

1. Для обновления с v3.2 заменить `src/index.js` и `package.json`, добавить
   `src/polls.js`, обновить `README.md` и добавить `test/polls.test.js`.
   Сохранить рабочий `src/anti-spam.js`, `.env` и картинку
   `assets/verification-banner.png`.
2. Загрузить изменения в подключённый к Render репозиторий GitHub и развернуть
   обновлённый коммит. Новых обязательных переменных окружения нет.
3. В Discord поднять роль AoS Security ВЫШЕ ролей ботов, которых он должен банить.
   Дать AoS права «Банить участников», «Управлять сообщениями», «Модерировать участников»
   и «Управлять вебхуками», а также доступ к защищаемым каналам и к каналу логов.
   Для резервного исключения нужно право «Выгонять участников».
4. Проверить `/security-status`: версия должна быть `3.3.0`, необходимые права — ✅.
   Если бот не запущен или отключён от Discord, он не может обрабатывать сообщения.
5. Выдать AoS права для голосований, описанные выше. После запуска бот сам
   регистрирует `/poll` и `/poll-photo` вместе с четырьмя прежними командами.
   Создать один обычный опрос и один опрос с двумя фото; проголосовать с двух
   аккаунтов и проверить результаты. После перезапуска результаты должны остаться.

Порядок ролей ограничивает бан даже при наличии Administrator:
[документация Discord](https://docs.discord.com/developers/topics/permissions#permission-hierarchy).
Входящий вебхук удаляется с правом Manage Webhooks:
[документация Discord](https://docs.discord.com/developers/resources/webhook#delete-webhook).

## Пороги и проверка

По умолчанию: 8 сообщений за 8 секунд, либо 6 разных пользователей/ролей,
упомянутых в одном сообщении, либо 2 сообщения с фактическим пингом
`@everyone`/`@here` в пределах окна. После срабатывания новые сообщения этого
отправителя также очищаются в течение минимум 30 секунд; при продолжающейся
активности этот период продлевается.

- `SPAM_MESSAGE_LIMIT`: целое число 2–100, по умолчанию 8.
- `SPAM_WINDOW_SECONDS`: целое число 1–300, по умолчанию 8.
- `SPAM_TIMEOUT_MINUTES`: целое число 1–40320, по умолчанию 5.

Если доверенный сервисный бот должен превышать эти лимиты, его конкретный ID
можно добавить в `WHITELIST_USER_IDS`. Такой ID полностью исключается из проверки;
роль Administrator для бота такого исключения не даёт.

Локальные тесты: `node --test` или `npm test` из корня проекта. Они проверяют
обычного бота, бота-администратора, несколько каналов, людей, вебхуки,
отсутствие прав, ошибки API, одновременные события и очистку очереди.
Тесты подменяют Discord API и не подключаются к живому серверу.
Тесты голосований также проверяют сериализацию через discord.js, права в канале,
ограничение повторных команд, загрузку фотографий, ошибки отправки и регистрацию
новых команд. Для них сначала выполните `npm install`, затем `npm test`.

## Роли

Роль AoS Security должна быть выше:

1. AoS Security
2. Verified
3. Unverified
4. другие защищаемые роли

Чтобы Anti-Nuke мог снимать опасные роли, роль AoS Security должна находиться выше этих ролей.

## Access Control

AoS Security v3 поддерживает 4 уровня:

- `OWNER` — полный доступ.
- `SECURITY ADMIN` — управление защитой.
- `MODERATOR` — только просмотр статуса.
- `MEMBER` — только обычное использование и верификация.

Переменные Render:

```text
OWNER_USER_ID=ID_главы

SECURITY_ADMIN_ROLE_IDS=ID_роли1,ID_роли2

MODERATOR_ROLE_IDS=ID_роли1,ID_роли2
```

Права команд:

```text
/security-status
MODERATOR+

/verification-setup
SECURITY ADMIN+

/lockdown
SECURITY ADMIN+

/panic
SECURITY ADMIN+
```

Владелец Discord-сервера автоматически получает `OWNER`.
